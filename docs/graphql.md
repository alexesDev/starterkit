# GraphQL

One endpoint, `POST <BasePath>/graphql` (default `/_system/starterkit/graphql`),
generated by [gqlgen](https://gqlgen.com) from `internal/graph/schema.graphqls`.
Schema first: edit the SDL, run `make gqlgen`, implement whatever stub appears.

## Resolvers are adapters

A resolver translates and delegates. It contains no logic:

```go
func (r *adminMutationResolver) BanUser(ctx context.Context, obj *model1.AdminMutation, input model.BanUserInput) (model.BanUserOrErrorPayload, error) {
	return r.env(ctx).BanUser(ctx, input)
}
```

`r.env(ctx)` pulls the request-scoped env — during a mutation, that is the
transaction-scoped copy.

## The admin namespace

```graphql
type Query {
  viewer: Viewer!
  admin: AdminQuery!
}

type AdminQuery {
  users: UsersConnection!
  user(id: Int64!): AdminUser
  admins: AdminsConnection!
  auditLog(limit: Int64! = 50, before: Int64): AuditLogConnection!
  buildGitCommit: String!
}
```

`AdminQuery` is an empty marker struct. Its resolver is the gate:

```go
func (r *queryResolver) Admin(ctx context.Context) (*model1.AdminQuery, error) {
	err := r.checkAdmin(ctx, ast.Query)
	if err != nil {
		return nil, err
	}

	return &model1.AdminQuery{}, nil
}
```

`checkAdmin` asks the `admins` table, not a role baked into a token — so
revoking admin takes effect on the next request.

The check runs **once**, when the namespace resolves. Every field underneath is
gated by construction — adding a new admin field cannot forget the check,
because there is no place to forget it. Add a field directly to `Query` and it
is public; that asymmetry is the point.

Denied attempts are written to `audit_log`. See [auth-dex.md](auth-dex.md).

## A command owns its transaction

Resolvers are adapters. Each mutation field calls a command method on `app`, and
that method decides what is atomic:

```go
func (a *app) BanUser(ctx context.Context, input banuser.Input) (banuser.Payload, error) {
	return runInTx(ctx, a, func(txCtx context.Context, env *app) (banuser.Payload, error) {
		return banuser.Resolve(txCtx, env, input)
	})
}
```

`runInTx` opens a write transaction, commits when the case returns no error and
rolls back otherwise. A command that must call a third party before its single
insert simply omits `runInTx` — one Go line of difference, visible where the
sequencing happens.

The boundary sits here rather than on the whole GraphQL operation because a
mutation that must call out, then write several rows atomically, then call out
again cannot be expressed at all when the transaction *is* the operation.

Two consequences worth knowing:

**Commit is decided by the case's error, not by the response.** A case that
reports a domain failure as `(&ErrorPayload{...}, nil)` returns no error, so its
transaction commits — correct for a case that wrote nothing, which is the normal
shape. A case that writes and *then* decides it failed must return a real
`error`.

**Admin fields under the namespace run concurrently.** GraphQL executes root
mutation fields serially, but the real mutations live under `admin` and gqlgen
dispatches those with `out.Concurrently`. Each has its own transaction, so two
of them in one operation are two independent transactions contending for the
single writer — they serialise, but do not rely on ordering between them.

A case package never opens a transaction: it is written to compose inside one.
A command method calls `Resolve`, never another command method, or it trips
`ErrNestedTransaction`.

For code with no HTTP request in scope — jobs, cron, boot — use
`app.WithTransaction` instead. Both share the same nested-transaction guard: the
write pool holds one connection, so a nested `BeginTx` would deadlock against
the transaction already holding it. `cmd/server/tx_test.go` covers this.

## Connection types

Two shapes, deliberately:

```graphql
type UsersConnection {
  totalCount: Int64! @goField(forceResolver: true)
  nodes: [AdminUser!]! @goField(forceResolver: true)
}
```

**Both** fields are forced resolvers, and the parent returns an empty marker:

```go
func (r *adminQueryResolver) Users(ctx context.Context, obj *model1.AdminQuery) (*model.UsersConnection, error) {
	return &model.UsersConnection{}, nil
}
```

That is the whole point of the shape — each field costs a query only when it is
selected. Computing `totalCount` eagerly in the parent looks harmless and
quietly undoes it: a client asking for `nodes` alone would still pay for the
count. If a connection field is not a forced resolver, work is happening that
somebody did not ask for.

```graphql
type AuditLogConnection @goModel(model: "starterkit/internal/graph/model.AuditLogConnection") {
  totalCount: Int64!
  nodes: [AuditLogEntry!]!
  pageInfo: PageInfo!
}
```

The audit log is resolved eagerly and bound to a hand-written struct, because a
keyset page and its `hasNextPage` come from one query — splitting them across
resolvers would only mean running it twice.

## Binding to database rows

```graphql
type User @goModel(model: "starterkit/internal/db.User") {
  id: Int64!
  email: String!
  name: String!
  createdAt: Timestamp!
}
```

The GraphQL object *is* the sqlc row struct. No mapping layer. Note what this
buys beyond convenience: `users.oidc_subject` exists on the Go struct but is
absent from the GraphQL type, so it cannot be selected. Exposure is opt-in per
field.

`autobind` in `gqlgen.yml` does this by name for `internal/db` and
`internal/model`; `@goModel` is for when the name does not match or autobind
picks the wrong candidate.

## Scalars

`Int` is pinned to 32-bit, per the GraphQL spec. Database ids are `int64` and
travel as the custom `Int64` scalar. Using `Int` for an id is a silent overflow
waiting for row 2147483648.

There is no `Time` scalar. A time is an object:

```graphql
type Timestamp @goModel(model: "starterkit/internal/dbtime.Stamp") {
  unix: Int64!
  formatted(layout: String! = "2006-01-02T15:04:05Z07:00"): String!
}
```

bound onto the Go type every time column already maps to. gqlgen resolves its
fields straight to methods on that struct, so no resolver is generated and no
field on any parent model needs one. A screen asks for the string it renders —
`createdAt { formatted(layout: "2006-01-02 15:04") }` — and no formatting logic
ships to the browser. See [rules.md](rules.md).

## When a mutation starts carrying a secret

Nothing in this schema does, so nothing redacts. `auditVariables` in
`internal/graph/audit_entry.go` writes the operation's variables into
`audit_log.detail` verbatim, which is what makes the behavioural snapshot worth
reading — the inputs are part of the record.

The day a mutation takes an API key, a password or a token, that stops being
safe and three things have to happen together:

1. Declare `directive @sensitive on INPUT_FIELD_DEFINITION | FIELD_DEFINITION`
   and mark the field.
2. Give it a runtime implementation in the `DirectiveRoot` passed to
   `generated.NewExecutableSchema`. gqlgen refuses to unmarshal an argument
   whose directive has no implementation, and it fails the whole field at
   request time, before any resolver runs — a failure every unit test passes
   through.
3. Redact in `auditVariables` before the JSON is written, walking the
   *operation against the schema* rather than the variable's own type.
   Sensitivity is a property of where a value is used: `@sensitive` sits on an
   input field, and a caller is free to declare the variable as a bare `String`
   and spread it into that field.

Step 3 is the one that gets missed. A redactor that walks the variable's
declared type looks correct and leaks anyway.

Shipping the directive before its first user would be a mechanism that does
nothing, which [rules.md](rules.md) forbids — hence a note here instead of dead
code there.
